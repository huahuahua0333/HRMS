# 企业员工管理系统（HRMS）

基于 **Django 4.2 + MySQL + Bootstrap + ECharts** 的企业员工管理系统，涵盖组织架构、人事档案、考勤薪资、公告任务、RBAC 三级权限、数据可视化与 AI 智能助手等完整功能。本项目可作为 Web 课程设计、Django 学习实战与二次开发的参考蓝本。

---

## 一、项目简介

本系统面向中小企业的人事管理场景，围绕“部门—员工—管理员—考勤—薪资—公告—任务”这条主线构建了一套完整的后台管理闭环。系统采用经典的 Django MTV 架构：视图层负责业务逻辑与权限判断，模型层通过 ORM 映射 MySQL 数据表，模板层基于 Bootstrap 3 渲染响应式后台页面，前端通过 jQuery Ajax 完成局部刷新与弹窗交互。

在基础人事功能之上，项目额外实现了：

- **RBAC 三级权限体系**：超级管理员、部门管理员、普通员工三种角色，既在中间件层做登录校验与 URL 拦截，又在视图层按角色做数据隔离；
- **AI 智能助手**：通过兼容 OpenAI Chat Completions 协议的大模型接口，提供智能对话、招聘 JD 生成、公司制度问答、数据智能点评四类能力，并按角色隔离喂给模型的数据快照；
- **数据可视化**：基于 ECharts 渲染部门人数、薪资趋势、考勤统计等业务图表，数据由后端接口聚合后返回 JSON；
- **工程化实践**：通用分页组件、BootStrap 表单混入类、ORM 关联查询优化、结构化日志、安全响应头与一套覆盖核心模块的单元测试。

## 二、技术栈

## 三、功能模块一览

### 1. 登录与账户

- 账号密码登录，密码以 MD5 摘要存储，不保存明文；
- 图片验证码校验，防止暴力登录；
- 登录成功后把用户 ID 与用户名写入 Session，按角色跳转到对应默认首页；
- 注销时清空会话。

### 2. 部门管理

- 部门的新增、编辑、删除；
- 部门列表联动显示在职员工数量；
- 支持 **Excel 批量导入部门**：读取上传文件第一个工作表的第一列，从第 2 行开始解析，自动跳过空行与空白名称，按部门名去重，重复部门不会重复入库；
- 仅超级管理员可新增部门与批量导入。

### 3. 员工管理

- 员工档案的新增、编辑、删除；
- 手机号唯一校验、格式正则校验；
- 头像上传（ImageField，文件存入 media 目录，库内保存相对路径）；
- 按部门等条件筛选与列表统计；
- 普通员工只能查看本人档案，部门管理员可查看本部门员工。

### 4. 管理员管理

- 后台管理员账户的新增、编辑、删除与重置密码；
- 新建/编辑表单支持二次确认密码、两次密码一致性校验；
- 为管理员分配角色（多对多）。

### 5. 考勤管理

- 考勤记录的录入、编辑、删除；
- 考勤状态枚举：按时、迟到、早退、缺勤、请假；
- 记录上下班打卡时间与日期。

### 6. 薪资管理

- 薪资记录登记与维护；
- 实发工资 = 基本工资 + 奖金 − 扣款；
- 按月份归档，支持列表查看。

### 7. 公告中心

- 公告发布、编辑、置顶切换；
- 支持调用 AI 根据标题与要点扩写正式公告正文；
- 公告按置顶与发布时间排序展示。

### 8. 任务管理（三级工作流）

- 任务字段：级别（紧急/重要/普通）、标题、详细信息、负责人、状态；
- 完整审批流：待完成 → 待审批 → 已完成 → 已归档，支持退回重做；
- 员工完成本人任务、部门管理员审批本部门任务、超级管理员查收归档；
- 列表按主键倒序分页展示，新建任务通过 Ajax 提交成功后局部刷新。

### 9. RBAC 权限控制

- 角色表与权限表多对多关联，权限可绑定对应 URL；
- 中间件统一完成：白名单放行 → 登录校验 → 加载用户与角色 → 识别角色类型 → URL 拦截；
- 数据级隔离：普通员工只看本人负责的数据，部门管理员只看本部门数据，超级管理员查看全部。

### 10. AI 智能助手

- **智能对话**：结合当前角色可见的数据快照回答人事相关问题；
- **招聘 JD 生成**：根据岗位名称生成包含岗位职责、任职要求、薪资范围的岗位描述；
- **制度知识库问答**：以公司制度表内容作为上下文进行回答；
- **数据智能点评**：对考勤、薪资、任务分布等做汇总点评；
- 按角色隔离可见数据，普通员工不会拿到他人或全公司敏感数据；
- 全局悬浮小窗 + 独立助手页面两种入口；
- 客户端统一封装：未配置 Key、网络异常、超时、HTTP 错误、返回解析失败等情况均降级为友好中文提示，不让异常冒泡到页面。

### 11. 数据可视化

- 仪表盘页面：部门人数分布、薪资趋势、考勤统计等 ECharts 图表，数据由后端接口聚合后返回 JSON。

## 四、数据模型设计

| 模型 | 说明 | 主要字段 / 关系 |
| --- | --- | --- |
| Department | 部门 | title 部门名称；一对多关联员工 |
| UserInfo | 员工 | 姓名、密码、年龄、账户、入职时间、手机号、头像、性别；外键关联部门 |
| Admin | 后台管理员 | 用户名、密码、姓名；多对多角色；外键关联管辖部门与关联员工 |
| Role | 角色 | 角色名称；多对多权限 |
| Permission | 权限 | 权限名称、权限 URL |
| Attendance | 考勤 | 外键员工、日期、上下班时间、状态 |
| Salary | 薪资 | 外键员工、月份、基本工资、奖金、扣款、实发工资 |
| Notice | 公告 | 标题、正文、发布人、发布时间、是否置顶 |
| Task | 任务 | 级别、标题、详情、负责人（外键员工）、状态 |
| Policy | 公司制度 | 标题、类别、正文、是否启用、录入时间 |

## 六、快速开始

### 1. 环境要求

- Python 3.12（3.10+ 均可）
- MySQL 5.7 / 8.0
- 可安装依赖的 Python 虚拟环境

### 2. 拉取代码并安装依赖

```bash
git clone https://github.com/huahuahua0333/HRMS.git
cd HRMS
pip install -r requirements.txt
```

### 3. 配置数据库

先在 MySQL 中创建数据库：

```sql
CREATE DATABASE ems2 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

在 `ems/settings.py` 的 `DATABASES` 中确认或修改本机连接信息（库名、用户名、密码、地址、端口）。

### 4. 执行迁移建表

```bash
python manage.py makemigrations
python manage.py migrate
```

### 5. （可选）配置 AI 能力

在 `settings.py` 的 AI 配置区填写大模型接口地址、模型名与 API Key；留空时 AI 相关功能会返回“尚未配置”的友好提示，不影响系统其他模块。配置项包括：`AI_API_KEY`、`AI_API_BASE`、`AI_MODEL`、`AI_TIMEOUT`。

### 6. 启动开发服务器

```bash
python manage.py runserver 0.0.0.0:8000
```

浏览器访问 `http://127.0.0.1:8000/`，未登录会自动跳转到登录页。

### 7. 演示账号

系统内置超级管理员用于演示（实际使用前请修改密码）：

- 用户名：`admin`
- 密码：`admin123`

此外可在管理员管理中创建部门管理员与普通员工账号，体验不同角色看到的菜单与数据差异。

## 八、权限体系说明

系统权限分为两层：

1. **页面级（中间件）**：未登录一律跳转登录页；非超管访问管理员页面会被重定向；普通员工禁止访问新增、修改、删除类写接口。
2. **数据级（视图层）**：在查询集上按角色追加过滤条件——普通员工限定 `owner` 或 `employee` 为本人，部门管理员限定为本部门，超级管理员不加限制。

角色与权限通过 RBAC 表结构维护：管理员 ↔ 角色 ↔ 权限（URL）。新增角色或权限时，只需在后台或数据表中配置关联，无需改动代码。

## 九、关键实现要点

- **通用分页**：`Pagination` 组件接收请求与查询集，自动计算总条数、总页数并切片（QuerySet 切片翻译为 SQL 的 LIMIT/OFFSET），同时保留搜索条件生成页码 HTML。
- **表单样式混入**：`BootStrap` 混入类统一为字段加 `form-control` 与 placeholder；`bootstrap_exclude_fields` 列表中的文件上传字段保留原生外观。`BootStrapForm` 与 `BootStrapModelForm` 分别供普通表单与 ModelForm 复用。
- **ORM 优化**：部门、员工、任务等列表查询使用 `select_related` / `prefetch_related` 预加载关联对象，避免循环中的 N+1 查询。
- **头像上传**：员工头像通过 ImageField 经 ModelForm 自动保存到 `MEDIA_ROOT`，数据库只存相对路径。
- **安全加固**：安全响应头（禁止 MIME 嗅探、XSS 过滤、点击劫持防护）、HttpOnly 会话 Cookie、会话有效期限制、密码 MD5 存储。
- **日志**：按级别输出到控制台与轮转文件，AI 与接口异常均有 WARNING 级记录，便于排查。

## 十一、常见问题

**Q：访问上传的员工头像显示裂图？**
确认 `settings.py` 中 `MEDIA_ROOT`、`MEDIA_URL` 配置正确，且 `urls.py` 中已挂载 `media` 的 `re_path` + `static.serve` 路由；上传文件需存在于 `media/` 对应子目录。

**Q：AI 助手提示“尚未配置 API Key”或连接失败？**
检查 `settings.py` 中 AI 配置是否填写、网络能否访问模型接口、账户是否有可用额度；超时或频繁调用时按提示稍后重试或更换响应更快的模型。

**Q：Excel 导入部门后列表没有变化？**
确认上传文件第一个工作表第一列从第 2 行开始填写部门名；已存在的部门会被去重跳过，只有新部门才会入库。

**Q：普通员工为什么看不到某些菜单？**
菜单与按钮均按角色渲染；普通员工只保留本人相关的考勤、薪资、任务、公告与 AI 对话入口，管理类入口对其隐藏。
